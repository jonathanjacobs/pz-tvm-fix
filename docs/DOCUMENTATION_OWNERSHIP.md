# Documentation ownership

| Information | Canonical source |
| --- | --- |
| Public overview and release identity | `README.md`, `VERSION`, `CHANGELOG.md` |
| Normative runtime behavior | `REQUIREMENTS.md` |
| Implementation design and durable decisions | `ARCHITECTURE.md`, `adr/` |
| Planned work and exit criteria | `ROADMAP.md` |
| Repeatable test procedure | `TESTING.md` |
| Actual test outcomes | `VALIDATION_HISTORY.md` |
| Experimental evidence | `spikes/` |
| Deployment and rollback | `DEPLOYMENT.md` |
| Workshop publication | `STEAM_WORKSHOP.md` |
| Release gate | `RELEASE_CHECKLIST.md` |

## Update guidance

Audience: contributors and reviewers.
Use this when: deciding where a project fact belongs.
Update this when: a document gains, loses, or changes responsibility.
Do not update for: a one-off implementation detail.

Update the canonical source first. Link to it instead of maintaining duplicate specifications or validation narratives.
